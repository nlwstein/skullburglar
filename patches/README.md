# Local patches to external dependencies

Applied on top of the pinned checkouts in `~/repos/bots-recomp-ext/`. Re-apply after any
re-clone or version bump (`git -C <checkout> apply <patch>`), then rebuild + reinstall the SDK
(**both** RelWithDebInfo and Release — the bots build runs the installed Release `bin/rexglue`
for codegen) and regenerate with `FORCE=1 tools/rebuild.sh` (the codegen stamp ignores the SDK).

| Patch | Target | Why |
|-------|--------|-----|
| `rexglue-sdk/0001-codegen-real-fences-for-sync-lwsync.patch` | rexglue-sdk v0.10.0 | Codegen emitted PPC `sync`/`lwsync` as no-ops ("x86 has strong ordering"); wrong on arm64. Emits `__atomic_thread_fence` (seq_cst / acq_rel). Suspected cause of B-036. Upstream candidate (Q-003). |
| `rexglue-sdk/0002-debug-audio-dump-fps-log.patch` | rexglue-sdk v0.10.0 (after 0001) | Debug hooks, env-gated, no effect when unset: `REX_AUDIO_DUMP`, `REX_FPS_LOG`, `REX_NAN_LOG`, `REX_RP_LOG`. Not for upstream as-is. |
| `rexglue-sdk/0003-vulkan-hoist-shared-memory-uploads.patch` | rexglue-sdk v0.10.0 (after 0002) | **Perf, required for 30+ fps on Mac.** Shared-memory uploads (`vkCmdCopyBuffer` of CPU-written guest pages) used to end the open render pass; ~7k/s in gameplay = thousands of Metal render-pass restarts on a tiler. Now, if no draw already recorded in the pass reads the uploaded pages, the copy (+ barriers) is spliced into the deferred command stream *before* the pass's begin. ~98% hoisted; gameplay 22.0 → 37.5 fps (A/B runs 47/48). cvar `vulkan_hoist_shared_memory_uploads` (default on). Upstream candidate (Q-003). |
| `rexglue-sdk/0004-framerate-limit-and-vk-warning-dedupe.patch` | rexglue-sdk v0.10.0 (after 0003) | cvar `framerate_limit` (swaps/s, 0 = off; sleeps the command processor in `XE_SWAP`) for B-038 — app default 60. Vulkan debug messenger logs each distinct non-error message only at counts 1, 10, 100, … (MoltenVK primitive-restart warning spam). |
| `rexglue-sdk/0005-abort-on-unhandled-host-fault.patch` | rexglue-sdk v0.10.0 | POSIX signal handler returned when no handler claimed a SIGSEGV/SIGBUS/SIGILL → the faulting instruction re-executed forever (B-041: endless "Unhandled guest access violation" log, 100 MB). Now writes pc + fault address to stderr and `abort()`s, so the app's SIGABRT handler prints a backtrace. Upstream candidate. |
| `rexglue-sdk/0023-ios-tvos.patch` | rexglue-sdk v0.10.0 (after 0001–0022) | Experimental iOS / tvOS builds (`tools/ios/build.sh`). CMake: `REX_APPLE_EMBEDDED` for iOS and tvOS (CMake's `IOS` is iOS only), no recompiler CLI or install rules there, MoltenVK loaded directly without the Vulkan loader, and MoltenVK's AppKit/IOKit lookups pointed at UIKit/Foundation. Code: `REX_PLATFORM_IOS`, the guest memory as a Mach memory entry mapped with `vm_map` (no `shm_open` on iOS), MoltenVK from the app bundle, SDL's `uikit` driver and `SDL_main`. |
| `rexglue-sdk/0024-vulkan-external-memory-host.patch` | rexglue-sdk v0.10.0 (after 0023) | Enables `VK_EXT_external_memory_host` when the device has it, so the native renderer can import guest memory as a GPU buffer and read it in place on unified-memory GPUs. |
| `rexglue-sdk/0025-android.patch` | rexglue-sdk v0.10.0 (after 0024) | Experimental Android builds (`tools/android/build.sh`). CMake: `REX_ANDROID` (the Linux code paths plus `REX_PLATFORM_ANDROID`), no recompiler CLI or install rules, no X11/Wayland/ALSA/PulseAudio/PipeWire for SDL, bionic's libraries (no `pthread`/`rt`). Code: the Xenia-era Android pieces that were missing (`main_android`, `AndroidNativeWindowSurface`), SDL's `SDL_main` and Android window, fibers by a small stack switch (bionic has no `ucontext` functions), no robust mutexes, the executable folder found with `dladdr` (the app is a library), the Apple `clock_cast` fallback, a disc image the player picked (a `/proc/self/fd/<n>` descriptor the app holds) mapped from a duplicate of that descriptor, and the geometry-shader / fill-mode requirements off by default as on macOS. None of it touches the codegen key. |
| `rexglue-sdk/0026-texture-copyswap-16in32-count.patch` | rexglue-sdk v0.10.0 (after 0025) | `CopySwapBlock`'s k16in32 case passed the length in bytes as the count of 32-bit words, so it read and wrote 4x the length: past the end of a texture upload's last row, and past the 8-byte stack block in the CTX1 / DXT3A converters. Counts words now. Not in the codegen key. Upstream candidate. |
| `rexglue-sdk/0027-vulkan-prefer-discrete-gpu-with-dynamic-rendering.patch` | rexglue-sdk v0.10.0 (after 0026) | Automatic GPU choice (`vulkan_device` not set) tried devices in enumeration order, which on Windows often lists an integrated GPU first, and took the first that worked even without dynamic rendering (what the native renderer needs). Now discrete GPUs come first, then integrated, virtual and others, and a device without dynamic rendering is used only when no device has it. The existing emulation-feature scoring still decides ties. Not in the codegen key. |
| `rexglue-sdk/0028-codegen-plain-memory-stack-nophys.patch` | rexglue-sdk v0.10.0 (after 0027) | Opt-in codegen/compile switches, all off by default so generated code is unchanged: `REX_MEM_PLAIN` (guest loads/stores through `may_alias` non-volatile types, plus a compiler barrier at every loop head), `REX_STACK_NOPHYS` (r1-relative accesses skip the physical-mirror select). Measured: no fps change on Apple M4 or x86 (see the CPU-cost spike notes), kept as a patch for experiments. |
| `rexglue-sdk/0029-timer-queue-precise-sleep-and-frame-audio-counters.patch` | rexglue-sdk v0.10.0 (after 0028) | **Perf (CPU).** The timer queue spin-waited while nothing was due, keeping about a quarter of a CPU busy for the 1 ms KeTimeStampBundle timer alone. It now sleeps, polling for new items every 1 ms, with a high-resolution waitable timer on Windows so due items still fire within a millisecond (`REX_TIMER_QUEUE_SPIN=1` restores the old spin for A/B runs). Also counts frames over 33 ms and 50 ms in the fps log line, and logs SDL audio underruns every 10 s (frames played, silent fills, underruns, lowest queue depth, longest gap between guest frames). Not in the codegen key. |
| `rexglue-sdk/0031-xthread-warn-once-too-few-cores.patch` | rexglue-sdk v0.10.0 (after 0029; 0030 is on `feat/fps-counter`) | `XThread::SetActiveCpu` logged "Too few processor cores - scheduling will be wonky" on every call when the machine has fewer than 6 logical CPUs: 22,939 lines in one 4-thread laptop session (GitHub #12). Now once per run. Touches `src/system`, which is in the codegen key (`tools/ci/codegen_key.sh`), so the stored codegen output is rebuilt once. |

Regenerate the whole series from the SDK working tree with `python3 patches/regen.py`: it assigns hunks to
patches by file / keyword (extend `SERIES` there for a new patch) and verifies the series reproduces the tree
exactly. 0023-0027 sit outside `SERIES`: they apply after the series (0023 shares `memory_posix.cpp` with 0022), and all five are
edited as plain diffs (run `regen.py` on an SDK tree without them).
