# What a portable session may still write outside its folder (tools/portable_isolation_test.sh), one line each:
#   <Darwin|Linux|all> <extended regex on the full path>  # why it can't be avoided
# An entry needs a reason a player could accept; anything the game itself chooses to write belongs in the portable folder instead.
Darwin /var/folders/[^/]+/[^/]+/C/com\.apple\.metal/  # Apple's Metal runtime caches every shader it compiles under the per-user cache folder (confstr DARWIN_USER_CACHE_DIR). The game's own process writes it, for every Metal program, and neither an environment variable nor an API moves it (tried MTL_SHADER_CACHE_PATH, _DISABLE, _ENABLE, MTL_ENABLE_SHADER_CACHE, _DIRECTORY on 2026-11-24: no effect). It is the system's cache, kept small and cleaned by macOS.
Windows [\\]AppData[\\]Local[\\](NVIDIA[\\](DXCache|GLCache)|AMD[\\](DxCache|VkCache|DxcCache)|D3DSCache|Intel[\\]ShaderCache)[\\]  # The graphics driver (or Windows' Direct3D runtime) keeps its compiled-shader cache in the user's local folder, for every program. No environment variable moves it on Windows.
Windows [\\]Windows[\\]Temp[\\](NVIDIA|AMD)  # Same: a driver service writing for the game.
Windows [\\]LocalLow[\\](Intel|NVIDIA|AMD)[\\]  # The Intel graphics driver keeps its shader cache in the user's LocalLow folder (the sibling of the local app data folder: it followed the sandboxed LOCALAPPDATA), for every program. No environment variable moves it.
Windows [\\]bots\.exe$  # A Windows Firewall rule for the program (printed by the snapshot as FIREWALL <program path>): Windows writes it when the game first listens on a network socket (LAN co-op's system link) and the player answers its prompt, or when the launcher's Fix button runs with an administrator prompt. Documented in docs/FILES.md.
